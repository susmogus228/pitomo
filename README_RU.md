# Питомо 0.14.0

В 0.14.0 добавлены адресная книга и повтор заказа с актуальными ценами,
гостевая корзина с объединением при входе, фото и отмена удаления в корзине,
отметки покупки, фильтры отзывов и модерация жалоб с журналом действий.
[Функции и обновление 0.14.0](docs/V0.14.0.md).

В 0.13.1 исправлены замечания аудита: сохраняются черновики оформления и редактора
товаров, ошибки форм указывают нужное поле, неудачные фотографии отзывов можно
загрузить повторно. Каталог понимает виды питомцев и разделы, обновляет выдачу без
исчезновения карточек. Админка показывает рабочие очереди доставки и малые остатки;
выгрузки учитывают эти условия и содержат историю доставки. Иллюстрации облегчены.
[Исправления и проверка](docs/V0.13.1.md) · [Гайд следующих шагов](docs/NEXT_STEPS.md).

В 0.13.0 покупатель отслеживает доставку по трём этапам: «На складе», «В пути» и
«Рядом с вами». Администратор переводит заказ на следующий этап, отмечает прокол
шины, переворот грузовика или проблему с двигателем и снимает отметку после
устранения проблемы. При проблеме с двигателем кот чинит мотор под открытым
капотом, над которым поднимается дым.
На странице заказа грузовик, дорога и колёса двигаются во время доставки;
при поломке движение останавливается. Покупатель видит историю изменений.
[Доставка и API](docs/V0.13.md).

В 0.12.0 администратор добавляет до пяти фотографий товара, выбирает обложку и
редактирует галерею. Регистрация требует отдельного подтверждения обработки
данных для аккаунта; аналитика и рекомендации остаются добровольным выбором.
Сервер сохраняет версию, текст, ФИО и дату согласия. В профиле можно изменить
выбор и отозвать аналитику. Старым аккаунтам согласия не приписываются.
[Функции и API](docs/V0.12.md) · [Документы и границы реального запуска](docs/PRIVACY_KZ.md).

Локальный магазин для восьми групп питомцев. React + TypeScript + Vite работают
с FastAPI, SQLAlchemy 2, Alembic и PostgreSQL 16 через один адрес.
В магазине есть поиск и фильтры, карточки товаров, регистрация, избранное, корзина,
оформление заказа, личный кабинет и история заказов. Кот играет с клубком;
сайт учитывает системное ограничение анимации. Каталог разделён на 10 товарных
разделов, фильтры сохраняются в адресе страницы. При регистрации кот знакомится
с посетителем, при входе встречает его. [Обновление каталога](docs/catalog-v2.md).

В версии 0.9.0 покупатель может подтвердить получение заказа и оставить отзыв на
купленный товар. Каталог показывает хиты продаж и действующие скидки; администратор
задаёт процент и срок скидки. При доставке можно отметить точку на карте, а отдельная
страница показывает ближайшие ветклиники. Администратор видит заказы и точки
доставки в личном кабинете. [Правила и API обновления](docs/V0.9.md).

В версии 0.10.0 добавлены фото, редактирование и ответы на отзывы, рейтинг в
каталоге, отдельная админ-панель и учёт тестовых пополнений остатков. Фото отзывов
хранятся в отдельном Docker-томе. [Правила и API версии](docs/V0.10.md).
Для проверки с телефона и доступа при
выключенном домашнем ПК подготовлена [схема OCI VM + HTTPS](docs/ONLINE_TESTING.md).

В версии 0.11.0 администратор выгружает данные для аналитики в Excel и CSV
из каждого раздела панели. Выгрузки учитывают фильтры, цены на момент заказа
и отдельные статусы оплаты. Контакты покупателей добавляются только по выбору
администратора. [Состав выгрузок](docs/ADMIN_EXPORTS.md).
В разделе товаров доступны создание карточки с вариантами, редактирование
состава или материала, SKU и базовой цены. Пополнение остатков фиксируется
в журнале поступлений.
Адреса доставки и поиска ветклиник вводятся текстом. После подключения
Geoapify появляются подсказки для Казахстана, выбор адреса устанавливает точку
на карте. Без ключа сохраняется ручной ввод. [Подключение и ограничения](docs/V0.11.md).

Оплата: тестовый успех, отказ и повторная попытка, либо оплата при получении.
Магазин не списывает деньги. Доставка и получение отмечаются в заказе;
служба доставки и реальные платежи не подключены. [Контракт API](docs/PITOMO_API.md).

В версии 0.7.1 исправлены транзакции, конкурентные изменения корзины и остатков,
частичные обновления пользователей и товаров, SQL-пагинация и обработка ошибок.
Добавлены ограничения попыток входа, повторяемый checkout, проверки готовности,
контейнер API и CI. Подробности: [изменения 0.7.1](docs/V0.7.1.md),
[эксплуатация, backup и восстановление](docs/OPERATIONS.md).

## Windows: запуск одним кликом

Откройте `START.bat`. Он проверит WSL и Docker Desktop, установит отсутствующие
компоненты, создаст локальную `.env` со случайными ключами для нового проекта
или восстановит её из проверенных прежних контейнеров и поднимет PostgreSQL,
миграции, API и сайт. Браузер откроет `http://127.0.0.1:8080`.
В режиме разработки launcher добавит 48 отмеченных демонстрационных товаров.
Повторный запуск использует кэш образов и сохраняет настройки, пользователей и остатки.
Первичная настройка WSL может потребовать разрешения Windows и перезагрузки.

`STOP.bat` останавливает этот проект, `DIAGNOSTICS.bat` показывает состояние,
`CREATE_ADMIN.bat` создаёт администратора. Подробности и ограничения:
[инструкция для Windows](docs/WINDOWS.md). Архив содержит исходники приложения
и скрипты запуска; Docker скачивает контейнеры при первом запуске.

`START.bat` запускает локальную копию: она недоступна, когда ПК выключен.
Для отдельной онлайн-копии с тестовыми данными см.
[инструкцию проверки с других устройств](docs/ONLINE_TESTING.md).

При переносе установленного магазина на другой диск сохраните прежнее имя
Docker Compose в `.petshop-project-name`, чтобы использовать существующую базу.
[Порядок переноса и проверки](docs/DRIVE_RELOCATION.md).

## Архитектура

```text
FastAPI router + authentication
              ↓
           Service
              ↓
      Repository interface
              ↓
 SQLAlchemy repository + transaction
              ↓
         PostgreSQL
```

Доменные Product, User, Cart и Order используют обычные Python-объекты.
Сервисы принимают DTO проекта; транспортные DTO пока определены в Pydantic.
PostgreSQL обеспечивает блокировки между процессами. SQLite подходит для
однопроцессной разработки и быстрых тестов; проверки гонок запускаются на PostgreSQL.

## Установка с нуля через Docker

Потребуются Docker Desktop с работающим engine и Docker Compose v2.
Распакуйте проект, например в `D:\Projects\petshop-api`, и откройте PowerShell:

```powershell
Set-Location D:\Projects\petshop-api
Copy-Item .env.example .env
docker version
docker compose version
```

В новом `.env` задайте два разных случайных значения: `POSTGRES_PASSWORD` и
`PETSHOP_JWT_SECRET`. Пример генератора при установленном Python:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Выполните генератор дважды. В `PETSHOP_DATABASE_URL` подставьте пароль PostgreSQL:
`postgresql+psycopg://petshop:<password>@postgres:5432/petshop`.
Сохраните `.env` локально с ограниченными правами доступа.

```powershell
docker compose config --quiet
docker compose up --build --detach --wait --wait-timeout 120
docker compose ps
Invoke-RestMethod http://127.0.0.1:8000/ready
```

Compose инициализирует пустую схему или обновляет существующую базу до
`0012_v014`. Этот раздел описывает запуск API без интерфейса. Для магазина
используйте `START.bat` либо оба файла Compose из [инструкции Windows](docs/WINDOWS.md).
Новый каталог при отдельном запуске API пустой. Для демонстрационных данных выполните явно:

```powershell
docker compose exec api python -m app.db.cli seed
```

Команда seed откажется заполнять непустой каталог. Создайте первого администратора:

```powershell
docker compose exec api python -m app.admin.bootstrap --email admin@example.com --first-name Admin
```

CLI запросит пароль и подтверждение без отображения введённых символов.
Для автоматизации доступен `--password-stdin`; передавайте пароль через защищённый
канал стандартного ввода. Публичная регистрация создаёт customer.

API доступен на `http://127.0.0.1:8000`. Compose по умолчанию отключает Swagger.
Для локального изучения задайте `PETSHOP_DOCS_ENABLED=true` в `.env`, пересоздайте
API через `docker compose up --detach api` и откройте `/docs`.
Получите токен через `/api/v1/auth/login` и вставьте его в поле **Authorize**.
Swagger не сохраняет токен после перезагрузки страницы.

## Локальный Python и PostgreSQL

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev-lock.txt
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --detach --wait postgres
```

Для следующих команд выберите базу на loopback. Пароль возьмите из своего `.env`;
не помещайте реальный пароль в общие скрипты или историю репозитория.

```powershell
$env:PETSHOP_DATABASE_URL = 'postgresql+psycopg://petshop:<password>@127.0.0.1:5432/petshop'
$env:PETSHOP_ENV = 'development'
$env:PETSHOP_DOCS_ENABLED = 'true'
.venv\Scripts\python.exe -m app.db.cli upgrade
.venv\Scripts\python.exe -m app.admin.bootstrap --email admin@example.com --first-name Admin
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Приложение читает JWT secret из `.env`; переменные окружения имеют приоритет.
`app.db.cli` и Alembic требуют `PETSHOP_DATABASE_URL` в окружении процесса.
Ключ `--reload` используйте при локальной разработке. Docker запускает API без него.

`create_app()` создаёт runtime-приложение по конфигурации. Отсутствующий или
шаблонный JWT secret останавливает запуск. Фабрика не создаёт таблицы и не
подменяет PostgreSQL базой SQLite. Для тестов используйте `create_test_app()`:
она создаёт отдельную базу в памяти с demo-каталогом. Если передать ей URL,
она использует указанную базу без очистки и автоматического seed.

## Обновление с 0.7.0

1. Остановите запись в API и сделайте backup. Проверьте восстановление в отдельную базу.
2. Установите зависимости из нового lock-файла и задайте JWT secret.
3. Запустите `.venv\Scripts\python.exe -m app.db.cli upgrade` с URL существующей базы.
4. Запустите API и проверьте `/ready`, вход, корзину и заказы.

Миграции 0003/0004 сохраняют пользователей, password hashes, товары и историю заказов.
При конфликтующих после Unicode casefold SKU миграция прерывается с инструкцией
исправить данные. Она не выбирает товар для удаления автоматически.
Миграция 0003 требует подключения к базе для backfill; `--sql` её не выполняет.
Для отката данных используйте проверенный backup. Старые 0001/0002 оставлены
без изменения: прямой `alembic upgrade head` на пустой базе по историческим
правилам добавит demo-каталог. Для новой пустой установки используйте `app.db.cli upgrade`.

Новый алгоритм проверки JWT требует `sub`, `iat`, `exp` и HS256. Старые корректные
токены с тем же ключом продолжают работать до истечения срока. После смены ключа
пользователи входят заново. При входе PBKDF2-хеш с 310000 итераций обновляется
до 600000; пробелы в новом пароле имеют значение.

## Контракты API

- Публично: чтение каталога, регистрация, вход, `/health` и `/ready`.
- Customer: свой профиль, корзина и заказы. Admin: дополнительно управление каталогом и пользователями.
- Каталог использует SQL-фильтрацию, сортировку и пагинацию. Списки пользователей и заказов принимают `limit` (1–100, по умолчанию 50) и `offset` (от 0).
- `POST /api/v1/orders` принимает необязательный `Idempotency-Key`. Повтор с тем же ключом у того же пользователя возвращает созданный заказ и не трогает новую корзину. Для следующего заказа используйте новый ключ.
- Ответы 422 содержат `detail`: строку доменной ошибки или массив `{type, loc, msg}` для валидации. Входное тело и пароль не возвращаются.
- Попытки входа и регистрации ограничены по хешу email и адресу клиента. По умолчанию: 5 на email и 50 на IP за 300 секунд, отдельно для каждой операции. Считаются также успешные попытки. Ответ 429 содержит `Retry-After`.
- При подтверждённом конфликте данных API возвращает 409, при недоступности хранилища 503. Ответ об успешной записи отправляется после commit.

## Проверки и наблюдение

```powershell
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m pytest -q -m 'not postgresql'
.venv\Scripts\python.exe -m unittest discover -s scripts -p 'test_*.py'
.venv\Scripts\python.exe -m pip_audit -r requirements-dev-lock.txt --no-deps --disable-pip
```

Для тестов PostgreSQL задайте `PETSHOP_TEST_POSTGRES_URL` отдельной тестовой базы
и выполните `python -m pytest -q -m postgresql`. Тесты создают изолированные схемы.
Без этого URL pytest явно пропускает PostgreSQL-набор.

`/health` подтверждает работу процесса. `/ready` проверяет доступность БД,
таблицы, колонки и версию миграции; ошибка даёт 503.
`/metrics` доступен администратору и возвращает счётчики текущего процесса.
Приложение пишет JSON-события HTTP с request ID, шаблоном маршрута, статусом,
ID пользователя и временем обработки. Пароль, токен, тело и email в события не входят.

Workflow `.github/workflows/ci.yml` проверяет SQLite на Windows/Linux,
PostgreSQL, Ruff, зависимости и запуск Compose. Для production нужны HTTPS,
сбор логов, мониторинг и backup по инструкции [OPERATIONS](docs/OPERATIONS.md).
В архиве нет настроенного внешнего сервера или канала уведомлений.

## Границы версии

В проекте пока нет платежей, доставки, возвратов, восстановления пароля и refresh
токенов. Распределённое нагрузочное тестирование и отказоустойчивость кластера
не входят в этот релиз. Счётчики `/metrics` обнуляются после рестарта процесса.
