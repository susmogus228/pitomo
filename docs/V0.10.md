# Питомо 0.10.0: отзывы и управление магазином

## Покупатель

Покупатель может оставить оценку и отзыв после подтверждения получения товара в своём заказе. На странице товара доступны редактирование и удаление своего отзыва, до трёх фото, ответы другим покупателям и удаление своих ответов. Удалённый ответ остаётся в ветке с пометкой «Ответ удалён», чтобы ответы на него не теряли контекст. Средняя оценка и число отзывов видны в каталоге и на странице товара.

Администратор может опубликовать один закреплённый официальный ответ под отзывом. Его ответы в беседе тоже получают отметку магазина, но не закрепляются. В разделе `/admin/reviews` есть очередь отзывов и фильтр без ответа магазина.

Сервер проверяет владельца перед изменением отзыва, ответа или фото. Он принимает JPEG, PNG и WebP до 5 МиБ, ограничивает изображение 12 млн пикселей и сохраняет только перекодированный WebP под случайным именем. На отзыв или ответ разрешено до трёх фото. Для одного пользователя действует лимит 12 загрузок фото и 20 ответов в час.

## Администратор

Маршрут `/admin` содержит сводку, заказы, остатки, отзывы, скидки и пользователей. Интерфейс показывает обычному покупателю отказ; сервер отдельно проверяет роль для каждого административного API. Прямая ссылка на API без входа возвращает 401, с ролью покупателя — 403.

В разделе «Товары и остатки» администратор выбирает вариант, количество и причину тестового пополнения. Сервер атомарно увеличивает остаток и сохраняет запись в журнале с названием товара, вариантом, артикулом, прежним и новым остатком. Журнал показывает только пополнения; списания при заказах в него не входят.

## API

| Действие | Метод и путь |
| --- | --- |
| Изменить или удалить свой отзыв | `PATCH/DELETE /api/v1/products/{product_id}/reviews/{review_id}` |
| Добавить, изменить или удалить ответ | `POST /api/v1/products/{product_id}/reviews/{review_id}/replies`, затем `PATCH/DELETE .../replies/{reply_id}` |
| Добавить фото к отзыву или ответу | `POST .../photos`, multipart-поле `file` |
| Удалить своё фото | `DELETE .../photos/{photo_id}` |
| Получить сводку | `GET /api/v1/admin/dashboard` |
| Получить очередь отзывов | `GET /api/v1/admin/reviews` |
| Пополнить остаток | `POST /api/v1/admin/variants/{variant_id}/replenishments` |
| Получить журнал пополнений | `GET /api/v1/admin/replenishments` |

Административные маршруты требуют роль `admin`. Публичные фото доступны по `/media/reviews/<32-символьный-id>.webp`; Nginx и API отклоняют другие имена. При локальной разработке Vite направляет этот путь к API. Docker хранит фото в отдельном томе, который нужно копировать вместе с базой данных.

## Запуск и онлайн-проверка

На Windows запустите `START.bat` из распакованной папки. Он проверяет Docker/WSL, собирает контейнеры, выполняет миграции и открывает сайт. Для отдельной копии с доступом при выключенном домашнем ПК следуйте [инструкции по OCI VM и Tailscale Funnel](ONLINE_TESTING.md). Для реального размещения понадобятся аккаунты OCI и Tailscale; проект сам их не создаёт. Бесплатная VM может оказаться недоступной при создании или быть изъята как простаивающая, поэтому непрерывная доступность не гарантирована.

Демонстрационная оплата и оплата при получении служат для проверки заказа. Реальные списания денег и служба доставки не подключены.

## Проверка версии

Проверки перед упаковкой: полный набор Python-тестов, `ruff`, сборка TypeScript/Vite, 50 frontend-тестов и запуск отдельного Docker Compose-проекта с чистой PostgreSQL. В живом тестовом стенде проверены подтверждение получения заказа, создание и редактирование отзыва, загрузка и выдача фото, ответы покупателя и магазина, пересчёт рейтинга, доступ к админке и пополнение остатков. Скриншоты сделаны на экранах 390 и 1280 пикселей; мобильные страницы каталога, отзывов и админки не выходят за ширину экрана.

Этот тестовый стенд работает только на компьютере разработчика. Размещение на OCI и проверка публичного HTTPS-адреса остаются отдельным шагом после создания аккаунта.
