# Petshop API v0.4.1 — Swagger / OpenAPI QA patch

## Почему появилась версия 0.4.1

`v0.4.1` — patch-релиз после отдельной проверки Swagger UI и OpenAPI схемы версии `v0.4.0`.

Доменная бизнес-логика каталога, пользователей и корзины не менялась. Во время QA были найдены две patch-проблемы: Swagger не показывал часть реально поддерживаемых `401`, `404` и `409` ответов, а JWT decoder принимал редкий неканоничный Base64URL alias подписи, который декодировался в те же байты. Обе проблемы исправлены без изменения публичных endpoint и успешных JSON-контрактов.

По Semantic Versioning это именно patch:

```text
0.4.0 -> 0.4.1
```

Новой доменной функции нет, совместимость API сохранена.

## Что проверено

Swagger QA выполнялся отдельно от обычного набора тестов.

Проверены системные точки:

```text
GET /               -> 200
GET /health         -> 200
GET /docs           -> 200
GET /openapi.json   -> 200
```

`/docs` содержит Swagger UI и использует `/openapi.json` как источник схемы.

OpenAPI version:

```text
0.4.1
```

## Проверка ошибок

Проверены реальные ошибочные сценарии:

| Код | Сценарий |
|---:|---|
| `401` | запрос защищённого endpoint без Bearer JWT |
| `401` | неверный пароль при Login |
| `404` | отсутствующий товар |
| `404` | отсутствующий variant при добавлении в корзину |
| `409` | повторная регистрация того же email |
| `409` | duplicate SKU |
| `409` | недостаточный остаток товара |
| `422` | `quantity = 0` |
| `422` | некорректная пагинация |
| `422` | неполное/некорректное тело запроса |

В текущем API отдельный `400 Bad Request` не используется. FastAPI/Pydantic возвращает `422 Unprocessable Entity` для ошибок валидации параметров и JSON-тела.

## Что исправлено в Swagger

### 1. Документированы реальные коды ответов

Ранее, например, endpoint корзины мог реально вернуть:

```text
401
404
409
422
```

но OpenAPI показывал не все эти варианты.

В `v0.4.1` маршруты явно описывают runtime-ошибки.

Пример:

```text
POST /api/v1/cart/items

200 — корзина обновлена
401 — отсутствует/недействителен Bearer token
404 — variant не найден
409 — недостаточный остаток
422 — данные не прошли валидацию
```

### 2. Добавлена единая ErrorResponse schema

Файл:

```text
app/core/schemas.py
```

Базовый формат бизнес-ошибок:

```json
{
  "detail": "Описание ошибки"
}
```

Это позволяет Swagger отображать структуру ошибок рядом с endpoint.

### 3. Улучшено описание операций

В Swagger добавлены понятные `summary` для каталога, authentication, users и cart.

Например:

```text
Регистрация пользователя
Вход и получение JWT
Текущий пользователь
Получить свою корзину
Добавить вариант товара в корзину
```

### 4. JWT canonical Base64URL hardening

Во время повторного прогона обнаружен редкий случай: стандартный permissive Base64URL decoder может принять две разные текстовые строки как одни и те же байты, если отличаются только неиспользуемые младшие биты последнего символа.

Для JWT это нежелательно: изменённая текстовая подпись должна считаться изменённым токеном.

В `app/core/security.py` декодирование теперь:

1. проверяет допустимый unpadded Base64URL;
2. декодирует значение;
3. кодирует байты обратно;
4. требует полного совпадения canonical строки с исходной.

Поэтому любой non-canonical/tampered JWT отклоняется с `401`.

### 5. Bearer authorization

Защищённые endpoint имеют OpenAPI security scheme:

```text
HTTPBearer
```

Swagger отображает кнопку **Authorize**.

Порядок работы:

1. выполнить `POST /api/v1/auth/register`;
2. выполнить `POST /api/v1/auth/login`;
3. скопировать `access_token`;
4. нажать **Authorize**;
5. вставить токен;
6. вызывать `/users/me` и `/cart`.

В `v0.4.1` включено:

```text
persistAuthorization = true
```

Поэтому Swagger сохраняет введённую авторизацию при перезагрузке страницы в рамках браузера.

## Что не изменилось

`v0.4.1` не меняет:

- доменные классы `Product`, `User`, `Cart`;
- Repository/Service архитектуру;
- формат JWT payload и алгоритм HS256;
- алгоритм хэширования пароля;
- бизнес-логику корзины;
- текущие URL;
- JSON контракты успешных ответов;
- in-memory хранение.

То есть клиенты `v0.4.0` совместимы с `v0.4.1`.

## Обновление v0.4.0 → v0.4.1

Это patch-релиз Swagger/JWT QA без изменения постоянного хранилища.

1. Заменить код на v0.4.1.
2. Установить зависимости.
3. Перезапустить Uvicorn.
4. Проверить `/docs`, Bearer Authorize и cart-flow.
