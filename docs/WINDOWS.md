# Запуск Питомо в Windows

Распакуйте папку проекта на локальный диск, например в `D:\Projects\petshop-api`.
Не запускайте файлы внутри ZIP. Откройте `START.bat`.

Launcher проверит WSL 2.1.5+ и Docker Desktop. Если Docker отсутствует, он скачает
официальный установщик 4.93.0 для Windows x64, проверит SHA-256 и подпись Docker Inc,
затем установит приложение для текущего пользователя. Уже установленный Docker
он оставит на месте. Повреждённый файл в кэше он сохранит отдельно и скачает заново.
При первой настройке Windows может запросить права администратора для WSL,
перезагрузку или подтверждение условий Docker Desktop. После этого запустите
`START.bat` повторно. Windows ARM64 этот launcher пока не поддерживает.

Python, Node.js для сборки интерфейса, PostgreSQL и зависимости API работают внутри контейнеров. Docker скачивает
недостающие образы и использует кэш сборки для неизменённых зависимостей. Повторный
запуск не устанавливает Docker заново и не заменяет `.env`.

## После запуска

Дождитесь сообщения `Petshop is ready`. Launcher проверит API, сайт и прокси,
затем откроет `http://127.0.0.1:8080`. PostgreSQL доступен только внутри сети контейнеров.
В локальном режиме каталог содержит 48 демонстрационных товаров для кошек, собак,
птиц, грызунов и кроликов, рыб, рептилий, амфибий и беспозвоночных.
Повторное заполнение пропускает существующие товары и сохраняет их остатки.
`CREATE_ADMIN.bat` запросит email, имя
и пароль администратора; пароль не попадает в командную строку или журнал launcher.
Если указать существующего пользователя, команда назначит ему роль администратора
и установит введённый пароль.

Создайте покупателя через «Войти → Зарегистрироваться», добавьте товар в корзину
и оформите заказ. Тестовая оплата позволяет выбрать успех или отказ, затем повторить
попытку. При оплате при получении заказ остаётся неоплаченным до получения.
Деньги не списываются, реальная доставка и обработка полученных платежей не подключены.

Для локального HTTP в `.env` нужен `PETSHOP_ENV=development`; launcher создаёт его
автоматически только для новой конфигурации. Скопированный `.env.example` содержит
production: поменяйте этот параметр для локального запуска. Launcher сохранит файл
и остановится с пояснением, если режим не подходит. Production требует отдельной
настройки HTTPS и точного публичного hostname. По умолчанию nginx принимает
только localhost/127.0.0.1. Для отдельной онлайн-копии и доступа при выключенном
домашнем ПК см. [инструкцию OCI VM](ONLINE_TESTING.md).

API доступен отдельно на `http://127.0.0.1:8000`; Swagger при включённом
`PETSHOP_DOCS_ENABLED=true` находится по `/docs`. Браузер магазина использует
HttpOnly cookies, API-клиенты могут пользоваться отдельными Bearer-токенами.
Выход из магазина отзывает браузерную сессию, но не ранее выданный Bearer-токен.

Ручной запуск из папки проекта с заполненной `.env`:

```powershell
docker compose -f docker-compose.yml -f docker-compose.frontend.yml up --build --detach --wait
docker compose -f docker-compose.yml -f docker-compose.frontend.yml exec api python -m app.db.cli seed-pitomo
```

Перед обновлением существующей базы сделайте резервную копию по `docs/OPERATIONS.md`.
Миграции 0005 и 0006 сохраняют данные. Обратная миграция отключена: для отката нужен backup.
При обновлении с 0.8.0 launcher добавит 24 недостающих товара. Названия и картинки
старых демонстрационных позиций обновляются отдельной командой после просмотра
dry-run; порядок описан в [обновлении каталога](catalog-v2.md).

## Файлы управления

| Файл | Действие |
| --- | --- |
| `START.bat` | Проверка окружения, сборка, миграции, запуск и открытие браузера |
| `STOP.bat` | Остановка контейнеров данного проекта с сохранением базы |
| `DIAGNOSTICS.bat` | Версии, доступность Docker и состояние контейнеров |
| `CREATE_ADMIN.bat` | Создание или обновление администратора после запуска |

Для запуска без браузера:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\windows\petshop.ps1 -Action Start -NoBrowser
```

Параметр ExecutionPolicy применяется только к этому процессу PowerShell.
Launcher не меняет системную политику выполнения скриптов.

## Настройки и данные

Launcher создаёт `.env` один раз. Он генерирует отдельные случайные ключи для базы
и JWT и разрешает чтение файла текущему пользователю и SYSTEM. Сохраните `.env`
в приватной резервной копии вместе с резервной копией БД. В поставку проекта
секреты и данные не входят. Существующую `.env` launcher проверяет и сохраняет;
пустые обязательные значения нужно заполнить вручную.
Если `.env` пропала после распаковки новой версии поверх старой папки, launcher
может восстановить её из прежних контейнеров этого же Compose-проекта. Он проверяет
путь папки, метки контейнеров, том базы, адрес подключения и совпадение пароля;
ключи и пароль не выводятся в журнал. Если контейнеры удалены или проверка не
прошла, launcher останавливается без изменения базы: восстановите сохранённую
`.env` из приватной копии. Один том базы не содержит JWT-ключ приложения.

Порт API задаётся через `PETSHOP_HTTP_PORT`, по умолчанию 8000. Если Windows
резервирует этот порт или его занимает другое приложение, выберите свободный
порт в `.env` и повторите запуск. Не публикуйте API в локальную сеть без отдельной
настройки HTTPS и доступа: Compose привязывает его к `127.0.0.1`.

Имя Compose-проекта зависит от полного пути папки. Сохраняйте путь при обновлении
проекта. Перед переносом подготовьте backup БД и восстановление по
[инструкции эксплуатации](OPERATIONS.md). Ранее запущенные вручную Compose-проекты
могут иметь другое имя; launcher не переносит их базы автоматически.

`STOP.bat` определяет контейнеры по метке этого проекта, поэтому работает и при
повреждённой `.env`. Он сохраняет том PostgreSQL и не останавливает Docker Desktop
или соседние проекты. При отсутствующей `.env` launcher никогда не создаёт новые
ключи поверх существующего тома базы.

## Диагностика

Журналы находятся в `work\windows`. При ошибке Docker launcher сохраняет последние
строки сообщения и скрывает значения пароля, JWT и строки подключения из `.env`.
Диагностика не выводит полную конфигурацию Compose. Не публикуйте саму `.env`,
дампы базы или произвольные логи приложения.

На проверенном компьютере обновление Docker Desktop с 4.91.0 до 4.93.0 устранило
воспроизводимую ошибку `sailor-ingest.sock`: три штатных остановки и запуска прошли
без переименования runtime-папок. Перед обновлением сохранены настройки и VHDX.
Эта проверка относится к данному компьютеру; установку WSL на чистой Windows
в рамках проверки не повторяли.
