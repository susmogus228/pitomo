# Перенос установленного магазина на другой диск

Сохраните `.env`, загруженные фотографии и Docker-тома вместе с исходниками.
Перед переносом остановите магазин и Docker Desktop. Резервная копия виртуального
диска Docker сохраняет базу, образы и том фотографий. Инструкция Docker:
[backup and restore](https://docs.docker.com/desktop/settings-and-maintenance/backup-and-restore/).

## Имя проекта Docker Compose

Windows launcher вычисляет имя `petshop-<12 hex digits>` из полного пути папки.
Для переноса существующей установки сохраните её прежнее имя в файле
`.petshop-project-name` в корне новой папки. Нужное имя видно в прежнем
диагностическом логе в строке `Compose project:` или в именах контейнеров.

Файл содержит одну строку, например `petshop-746c877868e1`. Launcher использует
сохранённое имя после проверки формата. При неверном значении он останавливает
запуск, чтобы не выбрать другую базу. Храните этот файл вместе с локальной `.env`.
Архив исходников не включает идентификатор конкретной установки.

При обычной новой установке файл не требуется. Такая установка получает имя
из собственного пути и отдельные тома.

## Данные Docker Desktop

В Docker Desktop выберите Settings → Resources → Advanced → Disk image location.
Docker перенесёт виртуальный диск в выбранную папку. Подробности:
[WSL backend](https://docs.docker.com/desktop/features/wsl/).
После переноса проверьте новую папку в настройках и доступность прежних томов.

Папка программы Docker Desktop, журналы и пользовательские настройки могут
оставаться на C:. Расположение виртуального диска определяет, где растут данные
контейнеров, образов, базы и фотографий.

## Проверка проекта

1. Сверьте файлы старой и новой папок по SHA256, включая `.env`.
2. Сохраните прежнее имя Compose в `.petshop-project-name`.
3. Запустите `DIAGNOSTICS.bat` из новой папки и проверьте имя Compose.
4. Запустите `START.bat`; проверьте прежних пользователей, заказы и остатки.
5. Создайте ярлык на новый `START.bat` с новой папкой в поле «Рабочая папка».

Храните исходную копию и резервную копию Docker до проверки данных магазина.
Перенос на другой диск освобождает место, но сам по себе не устраняет сбои WSL
или нехватку оперативной памяти.

## Память при запуске

Windows launcher передаёт Docker CLI, Compose и Buildx `GOMEMLIMIT=128MiB`, если
переменная ещё не задана. Это мягкий бюджет памяти Go, а не жёсткий предел памяти
контейнеров: [описание Go runtime](https://pkg.go.dev/runtime#hdr-Environment_Variables).
После команды launcher восстанавливает прежнее значение, включая случай ошибки.
Настройка действует в процессе запуска и не меняет системные переменные Windows.

При первом запуске API получает 120 секунд на инициализацию до подсчёта неудачных
проверок здоровья. Успешная проверка сразу подтверждает готовность. Запускатель
ожидает готовности контейнеров до пяти минут. Проверка `/ready` по-прежнему
проверяет соединение с базой и версию схемы; отсутствующая схема или недоступная
база не считаются успешным запуском. Эти интервалы учитывают медленный запуск
под нагрузкой Windows.

Общий лимит WSL задаётся отдельно в `%USERPROFILE%\.wslconfig`. Для этого компьютера
с разрешения владельца применён профиль:

```ini
[wsl2]
memory=2GB
swap=4GB
swapFile=D:\\Docker\\DockerDesktopWSL\\swap.vhdx
```

Профиль относится ко всем дистрибутивам WSL 2 данного пользователя. Launcher
не создаёт и не заменяет `.wslconfig`; на другом компьютере лимиты нужно выбрать
с учётом доступной памяти. Формат и применение описаны в
[документации WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).
