# Выгрузки для аналитики

Администратор скачивает XLSX или CSV через `GET /api/v1/admin/exports/{dataset}`.
Используйте авторизацию магазина: браузерную сессию либо Bearer-токен администратора.
Гость получает 401, пользователь с ролью `customer` получает 403.

## Наборы данных

| `dataset` | Листы XLSX | CSV |
|---|---|---|
| `overview` | `Overview` | Один файл со счётчиками, суммами и товарами |
| `orders` | `Orders`, `OrderItems`, `DeliveryEvents` при наличии событий | ZIP с отдельными CSV и `Metadata.csv` |
| `products` | `Products`, `Variants` | Один файл, строка на вариант; поля товара повторяются |
| `replenishments` | `Replenishments` | Один файл с историей пополнений |
| `users` | `Users` | Один файл с ролями и статистикой покупок |
| `reviews` | `Reviews`, `ReviewReplies` | Один файл с `record_type=review/reply`, телами всех ответов и ID связей |
| `discounts` | `Discounts` | Один файл с текущими настройками скидок |
| `all` | Все перечисленные листы | ZIP с отдельным CSV на таблицу и `Metadata.csv` |

В каждом XLSX есть лист `Metadata`: время формирования, фильтры, область периода,
число строк в таблицах и смысл денежных показателей. Шапки используют английские
имена колонок для сопоставления при импорте. Excel сохраняет цены как числа,
SKU как текст, даты как даты; первая строка закреплена, фильтры включены.
CSV использует UTF-8 с BOM, разделитель-запятую и стандартное экранирование полей.

## Фильтры

| Параметр | Значение и область действия |
|---|---|
| `format` | `xlsx` по умолчанию; альтернативно `csv` |
| `date_from` / `date_to` | `YYYY-MM-DD`; оба граничных дня включены |
| `status` | `created` / `cancelled`; заказы, их строки, обзор, статистика пользователей |
| `payment_status` | `pending`, `demo_paid`, `failed`, `cod_pending`, `cancelled`; те же таблицы |
| `delivery_method` | `pickup` / `delivery`; те же таблицы |
| `delivery_stage` | `warehouse`, `in_transit`, `nearby`; заказы и связанная статистика |
| `delivery_incident` | `flat_tire`, `overturned`, `engine_failure`; те же таблицы |
| `received` | `true` / `false`; подтверждение получения |
| `stale_hours` | 1–8760; активные доставки без обновления дольше указанного времени |
| `queue` | `active`, `warehouse`, `in_transit`, `incidents`, `awaiting_receipt`, `received`; совпадает с очередью экрана |
| `stock_max` | 0–2147483647; товары хотя бы с одним вариантом с остатком не больше порога; все варианты выбранных товаров |
| `user_id` | Положительный ID покупателя; те же таблицы и статистика |
| `q` | До 100 символов: название, SKU, бренд, питомец или раздел каталога/скидок; историческое название/SKU пополнения |
| `variant_id` | Положительный ID варианта в истории пополнений |
| `unanswered_only` | `true`: отзывы без закреплённого ответа магазина |
| `include_contacts` | `false` по умолчанию; `true` добавляет контакты в `Orders`/`Users`, текст проблемы и заметки событий доставки |

Экспорт охватывает подходящие записи со всех страниц. Параметры отображения списка
`page`, `limit`, `offset` не ограничивают выгрузку.

Для дат используем часовой пояс Казахстана `UTC+05:00`. Период
`date_from=2026-10-05&date_to=2026-10-05` соответствует интервалу
`2026-10-04T19:00:00Z <= created_at < 2026-10-05T19:00:00Z`.
В XLSX даты показываем в UTC+5 без зоны в ячейке; в CSV записываем суффикс `+05:00`.

Период относится к **созданию заказа, отзыва или пополнения**. Для выбранного отзыва
экспортируем его сохранившиеся ответы и ссылки на фотографии, включая ответы,
созданные позднее периода. `unanswered_only=true` проверяет закреплённый ответ
на момент выгрузки. Удалённые отзывы, ответы и фотографии пропускаем.

Каталог, остатки и скидки показывают текущий срез. Фильтр периода не восстанавливает
их прежнее состояние. В `Discounts` сохраняем настроенный процент, даты начала и конца,
а также `is_active_at_export`. В магазине пока нет истории всех изменений скидок.

Пример скачивания заказов за день:

```text
GET /api/v1/admin/exports/orders?format=xlsx&date_from=2026-10-05&date_to=2026-10-05&status=created
```

## История заказов и суммы

`OrderItems` сохраняет название, SKU, вариант, количество, цену покупки,
исходную цену и валюту из **снимка строки заказа**. Изменение или удаление товара
в каталоге не меняет эту выгрузку. Связи таблиц: `Orders.id=OrderItems.order_id`,
`Users.id=Orders.user_id`, `Products.id=OrderItems.product_id`.
После удаления товара последняя связь может указывать на исторический ID.
Заголовок товара в отзыве берём из его купленного заказа.

Считаем `line_total=unit_price*quantity` и
`line_discount=(original_unit_price-unit_price)*quantity`; если исходной цены нет,
скидка равна нулю. `Orders.total` суммирует строки заказа. Для заказа с несколькими
валютами записываем `currency=MULTI`, оставляем `total` пустым; суммы по валютам
сохраняются в `OrderItems` и обзоре.

В `Overview` используем группы:

- `all`: выбранные заказы, включая отменённые;
- `created`: заказы со статусом `created`;
- `cancelled`: отменённые заказы;
- `received`: действующие заказы с `received_at`;
- `demo_paid`: действующие заказы с тестовой оплатой `demo_paid`;
- `created_product`: количества и суммы действующих заказов по историческим
  названиям товаров, ID и валюте.

`received` и `demo_paid` могут пересекаться. Для общей суммы используйте строку
`created_order_value`; прибавлять к ней суммы полученных или тестово оплаченных
заказов не требуется. Счётчики заказов без валюты включают и заказы без строк.
Для разных валют формируем отдельные денежные строки.

Значения в обзоре описывают стоимость заказов. `demo_paid` означает тестовую оплату,
а подтверждение получения заказа с оплатой при получении может оставлять
`cod_pending`. Эти показатели не подтверждают поступление реальных денег и не
рассчитывают прибыль: в проекте пока нет закупочных цен и учёта приёма COD-платежа.

В `Users` сохраняем пользователей, роль, активность, число заказов и суммы
по выбранным заказам. При отсутствии заказов показатели равны нулю. Для пользователя
с несколькими валютами формируем строку на валюту, составной ключ `(id,currency)`.
Период и фильтры заказа меняют статистику, а список аккаунтов сохраняют.

## Контакты и защита файлов

По умолчанию `Orders`/`Users` содержат ID и аналитику. При `include_contacts=true`
добавляем email и имя покупателя, а в заказы также имя получателя, телефон, адрес,
комментарий и координаты доставки. Тексты отзывов и ответов остаются авторскими.
Фото экспортируем относительными ссылками `/media/reviews/{filename}` без бинарных
изображений.

В запросах выбираем поля по списку. Пароли, хеши токенов, браузерные сессии,
ключи идемпотентности и отпечатки checkout в файлы не включаем. Это выгрузка для
аналитики выбранных таблиц, а резервную копию БД нужно создавать отдельным процессом.

В XLSX строки сохраняем как текст, включая значения с `=`. В CSV добавляем
апостроф перед строками с потенциальными формулами (`=`, `+`, `-`, `@` после пробелов,
а также начальные табуляции/переводы строк). Числовые значения сохраняем числами.
Читатель CSV может убрать защитный апостроф при импорте как текст. Несовместимые
управляющие символы XML исключаем из текста при формировании файла.

Ограничения одной выгрузки:

- 100 000 обработанных строк, включая служебные и производные таблицы;
- 20 MiB текстовых данных и оценённых значений перед формированием;
- 50 MiB файла; для ZIP также 50 MiB суммарных CSV до сжатия;
- до двух одновременных выгрузок в процессе API.

Превышение объёма возвращает 413: сократите период или уточните фильтры.
При занятых слотах возвращаем 429 с `Retry-After: 3`. Некорректный период возвращает
422. Для ячейки XLSX длиной более 32 767 символов возвращаем 413 вместо обрезки;
CSV допускает такое поле в пределах общего объёма.

Готовый файл отдаём в ответе с `Content-Disposition: attachment`, `Cache-Control:
no-store`, корректным MIME и безопасным именем `pitomo-{dataset}-{UTC timestamp}`.
Не создаём постоянные файлы в публичных каталогах. В audit-событии сохраняем
ID администратора, набор данных, формат и число строк, без содержимого выгрузки
и значений контактных полей.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_admin_exports.py -q
```

Проверки охватывают роли, выгрузку за пределами страницы списка, границы дня UTC+5,
исторические цены после изменения каталога, суммы действующих/отменённых/полученных
заказов, тестовую оплату, контакты по запросу, состав CSV/ZIP, все ответы на отзывы,
поиск кириллицей, формулы, длинные ячейки и ограничение размера.
