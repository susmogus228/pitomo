# Проверка 0.7.1 с Windows launcher

Дата: 2026-09-29. `results.json` содержит результаты текущей проверки.
`backend-baseline-0.7.1.json` сохраняет исторический прогон до ремонта Docker;
его отметка о недоступности контейнеров относится к прежнему состоянию.

- Docker Desktop4.93.0, Engine29.8.1: три штатных остановки и запуска без изменения runtime-папок.
- Docker MCP:165 инструментов, ping/info/container/compose/host проверки прошли.
- Полный pytest с PostgreSQL16.15 в контейнере:201 passed,0 failed,0 skipped, включая16 PostgreSQL cases.
- Эксплуатационные скрипты:7 tests passed. Ruff,pip check и PowerShell parse прошли.
- Docker build, Compose startup, миграции и настоящий HTTP прошли. Корзина, заказ, остатки и права сохранились после перезапуска API и всего тестового Compose-проекта.
- Backup/restore в отдельную пустую базу: строки всех public-таблиц и sequences совпали. Защита от перезаписи dump и восстановления поверх данных прошла.
- Неудачное обновление контейнера вернуло прежний immutable image ID и готовый API.
- Windows PowerShell5.1:9 проверок вспомогательных функций и12 проверок полного запуска. Сам START.bat завершился с кодом0.
- Reviewer реализации указал3 замечания; исправления проверены. Reviewer безопасности:pass.

Frontend пока представлен согласуемым макетом. Рабочий frontend, удалённый CI,
публичный сервер и установка WSL на чистой Windows не входят в результаты этого
архива. Предыдущий аудит Python-зависимостей сохранён в историческом отчёте;
в этой итерации зависимости приложения не менялись.

`FILE_SHA256.json` фиксирует содержимое всех файлов архива, кроме самого manifest.
Проверка поставки сверяет CRC, каждый файл с исходником и manifest, синтаксис Python
и отсутствие локальных секретов. `.env`, дампы, Docker VHDX, виртуальные окружения
и служебная папка work в архив не входят.

Команды проверки находятся в README.md, docs/OPERATIONS.md и docs/WINDOWS.md.
